# Tutorial: Fetch YouTube transcripts from Apify and store them in Neon

How to replicate the Apify → Neon transcript pipeline used in `video2md`. The end result is a function `fetchAndSaveTranscript(videoId)` that reads from Postgres, falls back to Apify on a miss, and upserts the result.

Reference files in this repo:

- `lib/fetch-and-save-transcript.ts` — the main entry point.
- `db/queries.ts` — the upsert logic (`saveTranscriptToDb`).
- `db/schema.ts` — the table definitions.
- `workflows/steps/fetch-transcript.ts` — the workflow-step variant.

## 1. Prerequisites

## 2. The Neon + Drizzle client

Lazy initialization avoids touching `DATABASE_URL` at import time, which keeps tests and build-time imports from blowing up when the env var is absent.

```ts
// db/index.ts
import { neon } from "@neondatabase/serverless";
import { drizzle, type NeonHttpDatabase } from "drizzle-orm/neon-http";
import * as schema from "./schema";

type DbSchema = NeonHttpDatabase<typeof schema>;
let _db: DbSchema | null = null;

export function getDb(): DbSchema {
  if (!_db) {
    if (!process.env.DATABASE_URL) {
      throw new Error("DATABASE_URL is not defined");
    }
    _db = drizzle({ client: neon(process.env.DATABASE_URL), schema });
  }
  return _db;
}

export { schema };
```

Use `getDb()` from callers — `const db = getDb();`. Avoid wrapping the client in a `Proxy`: libraries that introspect the adapter (NextAuth, certain Drizzle migration tools) can hang or misbehave when `Proxy` intercepts property checks.

## 3. The schema (3 tables)

The transcript domain splits into three tables: a channel has many videos, and each video has at most one transcript snapshot.

```ts
// db/schema.ts
import {
  boolean,
  integer,
  jsonb,
  pgTable,
  serial,
  text,
  timestamp,
  unique,
  varchar,
} from "drizzle-orm/pg-core";

export const channels = pgTable("channels", {
  channelId: varchar("channel_id", { length: 64 }).primaryKey(),
  channelName: text("channel_name").notNull(),
});

export const videos = pgTable("videos", {
  videoId: varchar("video_id", { length: 32 }).primaryKey(),
  url: text("url").notNull(),
  title: text("title").notNull(),
  publishedAt: timestamp("published_at", { withTimezone: true }),
  channelId: varchar("channel_id", { length: 64 })
    .notNull()
    .references(() => channels.channelId, { onDelete: "cascade" }),
});

export const scrapTranscriptV1 = pgTable(
  "scrap_transcript_v1",
  {
    id: serial("id").primaryKey(),
    videoId: varchar("video_id", { length: 32 })
      .notNull()
      .references(() => videos.videoId, { onDelete: "cascade" }),
    channelId: varchar("channel_id", { length: 64 })
      .notNull()
      .references(() => channels.channelId, { onDelete: "cascade" }),
    description: text("description"),
    subscriberCount: integer("subscriber_count"),
    viewCount: integer("view_count"),
    likeCount: integer("like_count"),
    durationSeconds: integer("duration_seconds"),
    isAutoGenerated: boolean("is_auto_generated"),
    thumbnail: text("thumbnail"),
    transcript: jsonb("transcript").$type<
      { start: number; end: number; text: string }[]
    >(),
    createdAt: timestamp("created_at").defaultNow(),
  },
  (table) => [unique("unique_video_transcript").on(table.videoId)],
);
```

Two details that matter for the rest of the tutorial:

- Typing the `jsonb` column with `$type<...>()` makes Drizzle treat reads as the structured shape instead of `unknown`, so the cache-aware function in section 7 doesn't need a cast.
- The conflict target in the upsert below is `videoId` (via the named `unique_video_transcript` constraint), not the `serial` `id`. The `serial` PK still exists but isn't what we deduplicate on.

The `unique_video_transcript` constraint is what makes the upsert idempotent — fetch the same video twice and you update the existing row instead of duplicating it.

Generate and apply migrations with `drizzle-kit generate` (and your preferred runner — this repo runs them manually).

## 4. Validate the Apify response with Zod

The Apify actor returns snake_case. Validate the full shape so a silent schema drift becomes a loud, traced error rather than a corrupt DB row.

```ts
// lib/apify-schema.ts
import { z } from "zod";

export const TranscriptSegmentSchema = z.object({
  start: z.number(),
  end: z.number(),
  text: z.string(),
});

export type TranscriptSegment = z.infer<typeof TranscriptSegmentSchema>;

export const ApifyTranscriptResponseSchema = z.object({
  video_id: z.string(),
  url: z.string(),
  title: z.string(),
  published_at: z.string(),
  channel_id: z.string(),
  channel_name: z.string(),
  description: z.string().nullable(),
  subscriber_count: z.number(),
  view_count: z.number(),
  like_count: z.number(),
  duration_seconds: z.number(),
  is_auto_generated: z.boolean(),
  thumbnail: z.string(),
  transcript: z.array(TranscriptSegmentSchema),
});

export type ApifyTranscriptResponse = z.infer<typeof ApifyTranscriptResponseSchema>;
```

Then transform to a stable internal shape (camelCase, no string round-trip on the duration — keep it as a number):

```ts
// lib/transform-apify.ts
import type { ApifyTranscriptResponse, TranscriptSegment } from "./apify-schema";

export interface TranscriptResult {
  videoId: string;
  url: string;
  title: string;
  date: string;
  channelId: string;
  channelName: string;
  description: string | null;
  numberOfSubscribers: number;
  viewCount: number;
  likes: number;
  durationSeconds: number;
  isAutoGenerated: boolean;
  thumbnailUrl: string;
  transcript: TranscriptSegment[];
}

export function transformApifyResponse(d: ApifyTranscriptResponse): TranscriptResult {
  return {
    videoId: d.video_id,
    url: d.url,
    title: d.title,
    date: d.published_at,
    channelId: d.channel_id,
    channelName: d.channel_name,
    description: d.description,
    numberOfSubscribers: d.subscriber_count,
    viewCount: d.view_count,
    likes: d.like_count,
    durationSeconds: d.duration_seconds,
    isAutoGenerated: d.is_auto_generated,
    thumbnailUrl: d.thumbnail,
    transcript: d.transcript,
  };
}
```

## 5. Call the Apify actor

This codebase uses actor `Uwpce1RSXlrzF6WBA` (a YouTube transcript scraper). The pattern is: kick off a run, wait for it to finish, then read its dataset.

```ts
// lib/fetch-from-apify.ts
import { ApifyTranscriptResponseSchema } from "./apify-schema";
import { transformApifyResponse, type TranscriptResult } from "./transform-apify";

export async function fetchYoutubeTranscriptFromApify(
  videoId: string,
): Promise<TranscriptResult> {
  const { ApifyClient } = await import("apify-client");
  if (!process.env.APIFY_API_TOKEN) {
    throw new Error("APIFY_API_TOKEN is not defined");
  }

  const client = new ApifyClient({ token: process.env.APIFY_API_TOKEN });
  const actorRun = await client.actor("Uwpce1RSXlrzF6WBA").call({
    youtube_url: `https://www.youtube.com/watch?v=${videoId}`,
  });

  const { items } = await client
    .dataset(actorRun.defaultDatasetId)
    .listItems({ limit: 1 });
  const raw = items[0];
  if (!raw) throw new Error(`No results for video ID: ${videoId}`);

  const parsed = ApifyTranscriptResponseSchema.safeParse(raw);
  if (!parsed.success) {
    throw new Error(
      `Invalid Apify response: ${parsed.error.issues
        .map((i) => `${i.path.join(".")}: ${i.message}`)
        .join(", ")}`,
    );
  }
  return transformApifyResponse(parsed.data);
}
```

Two notes worth keeping:

- `await import("apify-client")` is dynamic so the SDK doesn't get pulled into bundles that never call it.
- `actor(...).call(...)` blocks until the run finishes. For long runs, switch to `start()` + polling.

## 6. Idempotent upsert into Neon

Three sequential upserts so foreign keys resolve in order: channel → video → transcript. The transcript row reuses one object for both `values` and `set` so the payload isn't repeated.

```ts
// db/save-transcript.ts
import { getDb } from "./index";
import { channels, scrapTranscriptV1, videos } from "./schema";
import type { TranscriptResult } from "@/lib/transform-apify";

export async function saveTranscriptToDb(data: TranscriptResult) {
  const db = getDb();

  await db
    .insert(channels)
    .values({ channelId: data.channelId, channelName: data.channelName })
    .onConflictDoUpdate({
      target: channels.channelId,
      set: { channelName: data.channelName },
    });

  await db
    .insert(videos)
    .values({
      videoId: data.videoId,
      url: data.url,
      title: data.title,
      publishedAt: data.date ? new Date(data.date) : null,
      channelId: data.channelId,
    })
    .onConflictDoUpdate({
      target: videos.videoId,
      set: { title: data.title, url: data.url },
    });

  const transcriptRow = {
    videoId: data.videoId,
    channelId: data.channelId,
    description: data.description,
    subscriberCount: data.numberOfSubscribers,
    viewCount: data.viewCount,
    likeCount: data.likes,
    durationSeconds: data.durationSeconds,
    isAutoGenerated: data.isAutoGenerated,
    thumbnail: data.thumbnailUrl,
    transcript: data.transcript,
  };

  await db
    .insert(scrapTranscriptV1)
    .values(transcriptRow)
    .onConflictDoUpdate({
      target: scrapTranscriptV1.videoId,
      set: transcriptRow,
    });
}
```

The `onConflictDoUpdate` clauses make the function safe to retry — important when this runs from a workflow step that may execute more than once.

## 7. The cache-aware entry point

Combine "read from DB first, fall back to Apify" into one function. This is what callers (server components, route handlers, workflow steps) actually use.

```ts
// lib/fetch-and-save-transcript.ts
import { eq } from "drizzle-orm";
import { getDb } from "@/db";
import { channels, scrapTranscriptV1, videos } from "@/db/schema";
import type { TranscriptSegment } from "./apify-schema";
import { fetchYoutubeTranscriptFromApify } from "./fetch-from-apify";
import { saveTranscriptToDb } from "@/db/save-transcript";

export interface TranscriptData {
  videoId: string;
  title: string;
  channelName: string;
  description: string | null;
  transcript: TranscriptSegment[];
}

async function getTranscriptFromDb(videoId: string): Promise<TranscriptData | null> {
  const [row] = await getDb()
    .select({
      videoId: videos.videoId,
      title: videos.title,
      channelName: channels.channelName,
      description: scrapTranscriptV1.description,
      transcript: scrapTranscriptV1.transcript,
    })
    .from(videos)
    .innerJoin(channels, eq(videos.channelId, channels.channelId))
    .innerJoin(scrapTranscriptV1, eq(videos.videoId, scrapTranscriptV1.videoId))
    .where(eq(videos.videoId, videoId))
    .limit(1);

  if (!row || row.transcript === null) return null;
  return { ...row, transcript: row.transcript };
}

export async function fetchAndSaveTranscript(videoId: string): Promise<TranscriptData> {
  const cached = await getTranscriptFromDb(videoId);
  if (cached) return cached;

  const fetched = await fetchYoutubeTranscriptFromApify(videoId);
  await saveTranscriptToDb(fetched);

  return {
    videoId: fetched.videoId,
    title: fetched.title,
    channelName: fetched.channelName,
    description: fetched.description,
    transcript: fetched.transcript,
  };
}
```

Returning a projection of `fetched` on cache-miss avoids a redundant round trip to Postgres right after we just wrote to it.

## 8. (Optional) Wrap in a Vercel Workflow for durability

The shape above runs fine inside a single request. For crash-safe retries, separate the network call and the DB write into `"use step"` functions and orchestrate them with `"use workflow"`.

```ts
// workflows/steps/fetch-transcript.ts
export async function fetchYoutubeTranscriptFromApify(
  videoId: string,
): Promise<TranscriptResult> {
  "use step";
  // ...same body as section 5
}

export async function saveYoutubeTranscriptToDb(data: TranscriptResult) {
  "use step";
  await saveTranscriptToDb(data);
}
```

```ts
// workflows/fetch-and-save-transcript.ts
export async function fetchAndSaveTranscriptWorkflow(videoId: string) {
  "use workflow";
  const cached = await getTranscriptFromDb(videoId);
  if (cached) return cached;

  const fetched = await fetchYoutubeTranscriptFromApify(videoId);
  await saveYoutubeTranscriptToDb(fetched);
  return fetched;
}
```

Heads-up — this codebase keeps a non-workflow `lib/fetch-and-save-transcript.ts` as well, because of two upstream issues (`vercel/workflow#618` and `#630`) that prevented calling step functions directly from RSC. If you only need a request-scoped operation, skip the workflow and use the plain function from section 7.

## 9. Using it

```ts
// app/api/video/[videoId]/route.ts
import { fetchAndSaveTranscript } from "@/lib/fetch-and-save-transcript";

export async function GET(
  _req: Request,
  ctx: RouteContext<"/api/video/[videoId]">,
) {
  const { videoId } = await ctx.params;
  const data = await fetchAndSaveTranscript(videoId);
  return Response.json(data);
}
```

## Summary of the moving parts

| Concern | File / function |
|---|---|
| DB client | `db/index.ts` (lazy `neon()` proxy) |
| Schema | `channels`, `videos`, `scrap_transcript_v1` |
| Apify call | `client.actor("Uwpce1RSXlrzF6WBA").call(...)` |
| Validation | `ApifyTranscriptResponseSchema` (Zod) |
| Transform | snake_case → camelCase + duration string |
| Save | 3-step upsert with `onConflictDoUpdate` |
| Cache + entry | `fetchAndSaveTranscript(videoId)` |
| Durability (optional) | `"use step"` + `"use workflow"` |

The two design choices worth copying: **validate the Apify shape with Zod before touching the DB**, and **make the save idempotent** so a retry never doubles your rows.
