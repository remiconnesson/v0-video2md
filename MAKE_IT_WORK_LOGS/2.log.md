# YouTube Transcript Fetching - Issue Log 2

## The Goal
Fix metadata extraction (currently returning `undefined` for title) and transcript retrieval for video `k1t2xyWMUdY`, which is currently failing with parser errors in `youtubei.js`.

## The Journey

### 1. Re-evaluating Metadata Extraction
- **Issue:** `basic_info.title` is returning `undefined`. Parser warnings show `Type mismatch`.
- **Hypothesis:** YouTube has changed the response structure, and `youtubei.js` 16.0.1 is failing to map some fields to `basic_info`.
- **Action:** Create a discovery script to dump the raw `info` object and look for alternatives.

### 2. Fixing Transcript Retrieval
- **Issue:** Both manual fetch and `getTranscript()` fallback failed.
- **Hypothesis:** If metadata parsing failed, `info.captions` might also be missing.
- **Action:** Investigate if we can extract caption URLs from other parts of the `info` object or if we need a different client configuration (e.g., `ANDROID` client).

### Experiment 7: Testing different Client Types
- **Attempted:** Tested `WEB`, `ANDROID`, and `TV_EMBEDDED` clients in a discovery script.
- **Outcome:**
    - `WEB`: Successfully retrieved metadata and caption tracks for `k1t2xyWMUdY` when `fetch` was correctly implemented.
    - `ANDROID`: Failed with `Cannot read properties of null (reading 'as')`.
    - `TV_EMBEDDED`: Failed with status code 400.
- **Learnings:** The `WEB` client is the most viable, but its success depends heavily on a robust `fetch` wrapper that correctly handles `Request` objects passed by `youtubei.js`.

### Experiment 8: Robust Fetch Wrapper for YouTube.js
- **Issue:** `youtubei.js` passes `Request` objects or `URL` objects to the custom `fetch` function. `undici.fetch` is strict about methods and bodies.
- **Action:** Improved the `fetch` wrapper to correctly extract `method`, `url`, and `body` from the input, and ensure `GET` requests never have a `body`.
- **Reasoning:** Inconsistent handling of `Request` objects was causing hidden failures during session initialization or metadata fetching, leading to `undefined` metadata.

### Experiment 9: Ensuring headers are passed in fetch wrapper
- **Issue:** `youtubei.js` sets critical headers (API keys, session tokens) on the `Request` object it passes to the `fetch` function. My initial wrapper only extracted `method` and `body`.
- **Action:** Updated the `fetch` wrapper to also propagate `headers` from the `input` (if it's a `Request` object) to the `undiFetch` call.
- **Reasoning:** Missing headers were likely causing InnerTube API calls to return incomplete or generic data, resulting in `basic_info.title` being `undefined`.

### Experiment 10: Case-insensitive method handling in fetch wrapper
- **Issue:** `youtubei.js` might use lower-case method names. My initial check `fetchInit.method === "GET"` was case-sensitive.
- **Action:** Switched to `method.toUpperCase() === "GET"`.
- **Reasoning:** Ensure `body` is correctly stripped for all `GET` and `HEAD` requests regardless of casing.
